# Stages split: databases and calls move to Stage 2

Date: 2026-11-11 20:58:56 UTC

Split the stages. Stage 1 is now only Kubernetes, the frontend, and the backend APIs: no business logic, no database, and no calls between services, so there is nothing to mock. `/health/ready` in Stage 1 succeeds once the service has started, the `store` and `client` directories are not created yet, and the tests only cover the logic and the handlers. The frontend is back in Stage 1. Stage 2 is no longer the MVP: it is now "Database and API call", where each service connects to its own database through `internal/store`, `/health/ready` checks the database, one service makes an API call through `internal/client`, and the database and the client are mocked in the tests (the mock text moved here from Stage 1). Which call is made is still to be decided. Renamed `docs/stages/stage-2-mvp.md` to `docs/stages/stage-2-database-and-calls.md`, and updated the links in `plan.md` (layout in 1.4 and the stage table in 2.3) and in the Stage 3 document. Stage 3 stays an empty placeholder. Added a sentence to `plan.md` 1.4 saying that `store` and `client` come in Stage 2. This follows a decision made in conversation. Earlier changelog entries that mention the old Stage 2 file name or the Stage 1 database and mock tests are historical and unchanged.
