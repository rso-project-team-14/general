# The read-only copy decision is back in the plan, in section 1.7

Date: 2026-11-11 21:34:28 UTC

Put the decision that `participation` builds its own read-only copy of the challenges from events back into the plan, as a new subsection "Read-only copy of the challenges in `participation` (decided)" at the end of `plan.md` section 1.7. It had been removed together with sections 2.1 and 2.2, which were emptied. The subsection restates: `participation` validates itself against its copy and does not call `challenge` on completion, the copy is built from `ChallengePublished` events and applied only when the version is higher, it holds only the contract fields, `challenge` provides the snapshot endpoint `GET /api/v1/challenges/snapshot` (service to service, not on the public gateway) for the bootstrap at startup with the events subscribed first, `/health/started` fails until the bootstrap is done, the consequences (works when `challenge` is down, eventually consistent), and that `participation` stays a separate service. Used one term, "snapshot endpoint", in sections 1.3, 1.7, and open decision 10, instead of "bootstrap endpoint" in some places, and the "see 1.7" pointer in 1.3 now leads to this text. The transactional outbox, which was only described in the removed section 2.2, is not restored. The removed 2.1 text is in git history, in commit 94fb32b. This follows a decision made in conversation and addresses item 8 of the review of the branch.
